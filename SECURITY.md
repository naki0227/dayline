# Security Policy

## Reporting a vulnerability

Do not open a public issue for vulnerabilities that could expose credentials,
private context, recordings, transcripts, browsing activity, or shell activity.

Use GitHub's private vulnerability reporting for this repository. Include the
affected component, reproduction conditions, expected impact, and any known
mitigation. Do not include real secrets or personal context in the report.

## Security-sensitive areas

Changes to capture, redaction, permissions, synchronization, Keychain access,
external connectors, signing, and release automation require explicit tests and
a security impact note in the work report.
